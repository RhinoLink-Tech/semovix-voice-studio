# 《Semovix Voice Studio｜VoiceStudio 能力吸收优先级清单》

## 一、总原则

这里的“吸收”分为三种方式：

1. **增强现有实现**：`semovix-voice` 已有基础，不重新建设。
2. **参考设计、独立实现**：借鉴 VoiceStudio 的架构和工程经验，不直接复制代码。
3. **延后引入**：等真实需求出现后再实施。

VoiceStudio 的仓库地址在这 /Users/kingnet/workspace/github_workspace/VoiceStudio
VoiceStudio 采用 AGPL-3.0，闭源产品不能默认直接复制或合并其核心代码；以下清单默认指**吸收能力、接口和工程方法，由我们独立实现**。

优先级定义：

| 级别 | 含义 |
|---|---|
| **P0-A** | 桌面 Beta 必须完成，没有就不能称为可交付客户端 |
| **P0-B** | 正式版必须完成，主要解决稳定性、可恢复性和可复现性 |
| **P1** | 第一版发布后的近期增强，显著降低安装和使用成本 |
| **P2** | 有明确场景后再做，不阻塞当前产品 |
| **不吸收** | 不符合当前产品边界，明确排除 |

# 二、P0-A｜桌面 Beta 必须吸收

## 1. Electron 桌面壳

| 项目 | 内容 |
|---|---|
| 当前状态 | `semovix-voice` 只有浏览器运行模式 |
| 吸收内容 | Electron Main、Preload、Renderer 容器、无浏览器外框窗口 |
| 实施方式 | 新增 `electron/`，复用现有 React Renderer |
| 禁止事项 | 不重做业务页面，不维护第二套桌面 UI |
| 验收 | 双击应用即可打开现有完整产品页面 |

VoiceStudio 证明了 React Renderer 可以同时服务于 Electron 和浏览器，桌面端并不需要另一套页面。它的桌面层负责窗口和本地运行时，实际 UI 仍是 React、Tailwind 和 Web 技术。

**落点：**

```text
electron/
├─ main/
├─ preload/
├─ shared/
└─ build/
```

## 2. Node 服务进程监管

| 项目 | 内容 |
|---|---|
| 当前状态 | 用户需要手工执行 Node 启动命令 |
| 吸收内容 | 启动、健康检查、异常退出检测、受控重启、退出清理 |
| 实施方式 | `NodeServerSupervisor` |
| 验收 | 无需终端即可启动；应用退出后无遗留 Node 进程 |

状态建议：

```text
checking
starting
ready
failed
stopping
```

## 3. Python Worker 进程监管

| 项目 | 内容 |
|---|---|
| 当前状态 | 依赖 `启动Worker.command` 手工运行 |
| 吸收内容 | Python 解释器解析、Worker 启动、健康检查、日志捕获、崩溃处理 |
| 实施方式 | `PythonWorkerSupervisor` |
| 验收 | Worker 不可达时可诊断；应用退出时 Worker 被完整终止 |

现有 Worker 已具备 CustomVoice、VoiceDesign、Base 和 Whisper 的独立懒加载，不需要重写模型层，只需要让桌面壳管理其生命周期。

## 4. 单实例与完整退出清理

需要吸收：

```text
单实例锁
第二次启动激活已有窗口
关闭前保存 UI 状态
停止任务轮询
停止 Node
停止 Worker
释放端口
清理临时目录
```

验收要求：

- 重复点击应用不会产生多个后台服务；
- 应用关闭后不存在孤立的 Python、Node 进程；
- 非正常关闭后，下次启动可以识别并处理残留端口。

## 5. 动态端口与同源 API

| 项目 | 内容 |
|---|---|
| 当前状态 | Node 默认 3000，Worker 默认 8800 |
| 吸收内容 | 端口冲突检测、动态端口、Renderer 同源 `/api` |
| 实施方式 | Electron 启动时分配端口并注入环境变量 |
| 验收 | 端口被其他程序占用时仍能启动 |

推荐链路：

```text
React Renderer
    ↓ /api
Node Express
    ↓ Worker HTTP
Python Worker
```

Renderer 不能直接访问 Worker。

VoiceStudio 采用同源 `/api` 代理，避免 Renderer 直接处理后端端口和 CORS，这一点应吸收。

## 6. 安全 Preload 与 IPC 白名单

必须吸收以下安全原则：

```text
contextIsolation = true
nodeIntegration = false
Renderer 不直接访问 fs
Renderer 不直接访问 child_process
外部链接交给系统浏览器
IPC 按具体动作白名单开放
```

首版只允许：

```typescript
window.semovoixDesktop = {
  getAppInfo(),
  getRuntimeStatus(),
  runDoctor(),
  restartWorker(),
  chooseDirectory(),
  chooseFile(),
  saveFile(),
  revealInFolder(),
  openLogs(),
};
```

不允许：

```text
执行任意 Shell 命令
读取任意本地路径
向 Renderer 暴露 process.env
返回 Python 或 Node 子进程对象
```

# 三、P0-B｜正式版必须吸收

## 14. 统一 Runtime Job 模型

当前声音设计和稳定性验证分别维护自己的任务状态。稳定性验证已经有：

```text
queued
warming
running
completed
failed
```

并持久化进度和测试产物。

需要抽成公共合同：

```typescript
interface RuntimeJob {
  id: string;
  type:
    | 'voice-design'
    | 'voice-clone'
    | 'validation'
    | 'synthesis'
    | 'transcription';

  status:
    | 'queued'
    | 'warming'
    | 'running'
    | 'succeeded'
    | 'failed'
    | 'cancelled';

  progress: {
    completed: number;
    total: number;
    stage?: string;
  };

  createdAt: string;
  updatedAt: string;
  error?: RuntimeError;
}
```

不是重写现有业务，而是统一其底层任务状态。

## 17. 重启恢复策略

不是所有任务都应该自动重跑。

建议：

| 任务状态 | 应用重启后 |
|---|---|
| queued | 可以恢复 |
| warming | 重新进入 queued |
| running 且无产物 | 标记 interrupted，可手工重试 |
| running 且部分完成 | 按已保存产物续跑 |
| succeeded | 不重复 |
| failed | 保留失败证据 |
| cancelled | 不恢复 |

VoiceStudio 在 Job、Job Event 和远程任务恢复方面积累较多，这种任务恢复原则值得吸收。

## 20. 模型版本精确锁定

Voice Profile 不能只记录：

```text
Qwen3-TTS-12Hz-1.7B-Base
```

还要记录：

```text
provider
repoId
revision / commit
localPathFingerprint
runtimeVersion
torchVersion
deviceType
```

例如：

```json
{
  "model": {
    "provider": "Qwen",
    "repoId": "Qwen/Qwen3-TTS-12Hz-1.7B-Base",
    "revision": "具体 commit SHA",
    "runtime": "qwen_tts x.y.z"
  }
}
```

否则同一个模型名更新后，历史声音无法真正复现。

## 21. 模型加载、卸载和显存释放

当前四个引擎在同一 Worker 进程内独立懒加载，但还需要明确：

```text
warmup
loaded
lastUsedAt
unload
unloading
memoryUsage
loadError
```

正式版最低要求：

- 可手工卸载；
- 一段空闲时间后可卸载；
- 加载失败后可重新加载；
- OOM 后不无限重启；
- UI 能看到哪个模型当前占用资源。

## 22. 引擎隔离 / Sidecar

这是 VoiceStudio 最值得吸收的运行时经验之一。

当前 `semovix-voice` 把四个重模型放在同一个 Python Worker。正式版建议演进为：

```text
Worker Supervisor
├─ CustomVoice Sidecar
├─ VoiceDesign Sidecar
├─ Base Sidecar
└─ Whisper Sidecar
```

也可以先采用折中方案：

```text
同一时刻只允许一个大型 Qwen 模型常驻
+
切换时显式 unload
```

优先目标不是多模型并发，而是：

```text
一个模型崩溃不拖垮全部 Worker
显存能够真正释放
模型切换可诊断
```

VoiceStudio 的模型 Sidecar 和进程隔离设计值得参考，但实现应根据我们的四个模型独立完成。

```text
semovix-voice-profile.zip

├─ validation-report.json
```

## 38. Web / Desktop 能力检测

同一 Renderer 需要知道运行环境：

```typescript
interface AppCapabilities {
  desktop: boolean;
  nativeFilePicker: boolean;
  runtimeSupervisor: boolean;
  autoUpdate: boolean;
  revealInFolder: boolean;

```

网页模式自动隐藏桌面专属入口，不能出现点击后无效的按钮。

VoiceStudio 的 Docker 网页模式就是复用同一 Renderer，并隐藏原生桌面能力。

## 43. Remote GPU Worker

触发条件：

- 本机没有足够 GPU；
- Mac 工作台需要调用 Linux CUDA 主机；
- 多台电脑共享一台 GPU；
- 任务需要在办公室服务器上持续运行。

吸收内容：

```text
Worker 注册
能力上报
模型列表
任务派发
断线恢复
任务 Deadline
Worker 版本协商
结果回传
```

VoiceStudio 的 Remote Worker 已支持注册、批准、模型能力匹配、任务恢复和断线重连等机制，可以作为参考。
